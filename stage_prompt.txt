# STAGE 1 — Fully automatic audits (no audit button)

**What I want:** nobody clicks "Run audit". The system syncs and audits **by itself every 24 hours**, and the UI shows a **countdown timer** to the next automatic audit.

**Backend**
- The schedule is **ON by default**: every 24 hours at a configurable time of day (default 02:00 Asia/Karachi). Each automatic cycle = (1) GitHub sync (if connected and dataMode is live) → (2) audit run → (3) snapshot/trend point → (4) notifications (Stage 4). Actor shown as "Automatic audit". Record `trigger: scheduled`.
- Robustness (the app may run on a PC that sleeps): on every startup and then every 5 minutes, check `last successful automatic audit`; if more than 24 h (+ 15 min grace) ago, run **one** catch-up audit immediately. Never burst-run multiple catch-ups. Overlap lock so two audits can't run at once. If the GitHub sync fails, still run the audit on the last synced data and mark the run `degraded` with the reason (shown in the report). Retry a failed sync once after 10 min.
- Endpoints: `GET /api/automation/status` → `{enabled, intervalHours:24, timeOfDay, nextRunAt, lastRun:{id,at,status,trigger}, secondsUntilNext, catchUpPending}`. `PUT /api/automation/config` → only `timeOfDay` and `enabled` (pause/resume). Pausing requires a note, writes an audit-log event, and the UI shows a clear "Automatic audits paused" warning everywhere the timer shows.
- **Remove the manual trigger from the product:** `POST /api/audits/run` must no longer be callable from the browser. Keep the audit service function for the scheduler and tests; expose a manual endpoint only when `ENV=dev` and `ALLOW_MANUAL_AUDIT=true` (default false).

**Frontend (this is an explicitly requested change to existing screens)**
- Remove the **"Run audit"** button (Access audit page header), the **"Run access audit"** button (Overview header) and any `data-run-audit` triggers. Do not leave empty gaps: replace them in the same spot with a compact **Next automatic audit** status chip in the existing badge/button-outline style: `Next audit in 05:42:10` (live ticking countdown, updates every second, uses server time offset so it's correct even if the PC clock is off) plus small text `Last audit: <time> · Automatic`.
- While an automatic audit is running, show "Audit in progress…" (the existing in-progress state), and refresh data automatically when it finishes (poll `/api/automation/status` every 15–30 s; on a new completed run, reload bootstrap and show a toast "Automatic audit completed").
- The existing "Latest completed audit" cards and "View full report" stay. The empty state text "Run an audit to create a snapshot" must be changed to "The first automatic audit runs <time>".
- Settings → the existing **Scheduled audits** card becomes **Automatic audits**: shows status, interval (fixed 24 h), time-of-day picker, pause/resume (with required note), next run and last runs list. Remove the daily/weekly/off options.
- Search palette / any other place offering "run audit": remove.

# STAGE 3 — Remaining rules: Separation of Duties (SoD) and orphan accounts

Add to the pure scoring module and to the rule-config card (each rule: enable flag, points, editable, versioned, previewable; defaults must not change existing results on the 12 sample records):
- **SoD — conflicting access pairs:** configurable table `sod_conflicts` (resource-pattern A × access level, resource-pattern B × access level, description). Example default: Admin on `*terraform*`/`*infra*` + Admin on `*payment*`/`*billing*`. A person who holds both → finding "Separation of duties conflict" with evidence for both assignments.
- **SoD — approval integrity (enforced, not just flagged):** a person can never approve or reject their **own** access request (compare the approving admin's email to the requester's email) → 409 with a clear message; recorded in the audit log as a blocked attempt.
- **Orphan rules:** (a) assignment whose identity is unmatched/unknown (exists), (b) identity with `active` status but zero assignments for N days (config), (c) repository with **no Admin/owner** or only **one** admin (bus-factor), (d) archived repository still granting Write/Admin, (e) outside collaborator with Admin/Write on a repo older than N days with no recent activity.
- Show these findings through the existing tables with new, clear reason text; recommended actions stay within the existing vocabulary (Revoke / Reduce / Keep) plus "Assign owner" for (c) rendered as plain text recommendation (no new buttons).
- Tests per rule (boundaries, enable/disable, preview). Update `docs\ENGINE.md`.
